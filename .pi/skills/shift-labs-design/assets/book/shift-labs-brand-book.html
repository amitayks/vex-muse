Orange means it fired

This is how Shift Labs documents look: research decks, reports, notes and figures. The language comes from the Agent Work Index decks. Warm paper, ink type, simple shapes, and one orange that marks the thing that happened. Every document works in light and dark, and dark mode is the Vex dashboard’s charcoal.

1signal colour. Orange marks what fired, the key bar and the one number to read.

2modes, same tokens: paper from the Agent Work Index, charcoal from the Vex dashboard.

15shapes, drawn from JSON, that explain a system or a number without a chart library.

1 · The logo

The logo, without a background

The logo is the Shift keycap: a pink face, a navy up arrow, and a darker lip that forms its border. We use it without any background, framed at its own border. The artwork itself is never changed.

45%of the official square’s width is logo. The rest was a white background, off-centre: 163 left, 117 right, 131 top, 149 bottom (of 512).
232 × 233the logo’s own frame in the official file. Its border is the outer edge of the lip.
22 : 2the lip border: 22 units along the bottom, 2 on the right, a hairline on the left, and it rises at the top-right corner.
80 · 11 · 9percent of the logo that is face, lip and arrow.
  1. No background, ever. No white square, no chip, no tile behind it. It sits directly on paper or charcoal.
  2. Never change the artwork. Do not recolour, redraw, round, mask, rotate, stretch, add a shadow, or build a lockup or wordmark from it.
  3. Size by height only. 16 px or larger. Keep a quarter of its width clear on every side.
  1. Where it goes. The page header and footer, the deck cover and the closing slide. It is never decoration inside content.
  2. How it ships. <img data-brand="logo">. The build embeds the pinned file byte for byte, and the lint checks its hash and rejects any white background.
  3. Colourways are for avatars. The 16 official colourways below are trimmed the same way. Documents use the original pink.

Orange is a signal, not a decoration. It marks the run that fired, the key bar, the eyebrow and one number per slide.

  1. Three orange tiers for text. --s-signal fills marks and large numbers. --s-signal-label sets bold caps labels. --s-signal-ink sets small orange text on tints, at 4.5:1 or better.
  2. Greys carry everything else. Rule grey for structure, muted for reading text, ink for what matters.
  3. Categories, not colours. Shapes show difference with position, outline and one signal. There is no rainbow palette.

4 · Layout

The slide

A 960 × 540 pt page with 68 pt margins. Every slide says one pattern in the same order: what it is, what it looks like, the rule, the number, and how we counted.

Pattern 3 of 8

A state changed

The sensor fires when something it already tracks is in a different state from the last run.

Save the fields you care about as one string, and fire when the string changes.

10%of sensors fire on a change

5 · Shapes

Ten shapes that explain a system

A shape is a small diagram drawn from JSON. Grey is structure. Orange is the event. Each one below is live: switch the mode and it redraws.

Each tick is one run. Orange runs fired.

ticks

Runs over time; the ones that fired are ringed. "style":"check" shows ✓ and ✗ with notes for alerts and recovery.


      

      

        

        
axis
Points on a line: reminders, a deadline window (spans, lines), or a day ("scale":"linear" with ticks).

A value over time. With a band it becomes “a number out of range”: the part outside turns orange, and the leave and return are marked.

      

      

        

        
shares
Ranked shares, high to low. The key bar is orange; null prints n/a, never a guess.

Left to right: list, code, store, event (with an else branch), agent, chip, box. Arrows turn orange after the event.

A list with a cursor. Items after the cursor are new and fire.

      

      

        

        
diff
The fields you track, last look against this look. Changed values turn orange and the sign becomes ≠.

Two systems that should agree. Each record without a partner gets a dashed orange link and fires once.

Stages that take on more. One step is active.

        7 · Voice
        
Plain words, one idea per sentence

        
The decks read like a field guide. Short present-tense sentences, the same term every time, and the reader’s job in the rule.

      

      

        
The sensor fires when an expected reply has not arrived within a set time.

        
Our intelligent monitoring seamlessly detects stalled conversations!

        
Keep a cursor and fire only for items after it.

        
It is recommended that cursors be leveraged to avoid duplicates.

        
45% of sensors fire on new items.

        
Over half of sensors (a majority!) are item-driven.

      

      
    
        
  1. Titles name the thing. “New items”, “What a sensor is”. A finding may lead a report title only when the number beside it proves it.
    2. 
        
  2. One term per idea. Sensor, run, turn, fire, cursor. Define each once, then never swap it for a synonym.
    3. 
        
  3. Examples are real and anonymous. Paraphrase, remove names, rewrite code sketches, and say so in How we counted.
    4. 
        
  4. No hype, no exclamation marks, no emoji. Sentence case in the source; the kit sets eyebrows and labels in capitals.
    5. 
      

    

  


  
  

    

      

        8 · Honest numbers
        
Every number says how it was counted

        
A reader should be able to trust a number without asking for the spreadsheet.

      

      

        
    
          
  1. A denominator in words. “of sensors”, “of the agent turns that sensors start”. A percentage without one fails review.
    2. 
          
  2. How we counted, on every slide with a number. Unit, source, weighting, exclusions, and any coding check.
    3. 
          
  3. Suppress, do not guess. Too few cases prints n/a. Never an estimate in its place.
    4. 
        

        
    
          
  1. Round visibly. Whole percentages in decks; when shares do not sum to 100, say it is rounding.
    2. 
          
  2. Recompute what you derive. Put data-calc="(1180-1000)/1000*100" on a derived number; the lint checks it.
    3. 
          
  3. State the data mode. Published, snapshot, live, sample or synthetic. Sample data never looks like published data.
    4. 
        

      

    

  


  
  

    

      

        9 · Decision-ready
        
A report is an argument for a decision

        
A report is not a decorated dataset. It helps a named reader make a named decision, and it claims no more than its data supports. The method is Dio’s; lint enforces what a machine can check.

      

      
Decision → metric contract → data QA → metric validation → matched comparison → decomposition → evidence ladder → chart by job → action gate → visible trust → artifact check

      

        
    
          
  1. Decision first. Write the job: reader, decision, what changes it. The first screen answers what changed, whether it is material, what moved it, what is at risk, what decision is required and what is still missing.
    2. 
          
  2. Every metric is a contract. Meaning, source, grain, calculation, exclusions, comparison, owner and action. If two people could compute it differently, it is not defined.
    3. 
          
  3. Arithmetic is not meaning. Totals that reconcile across every dimension say nothing about a claim the source holds no data for.
    4. 
          
  4. Compare like with like. Each KPI shows its matched prior period, plan or target. A missing cutoff is written “Not captured”.
    5. 
        

        
    
          
  1. Decompose the change. Rank parts by their share of the change, not their size, and make them sum exactly to the headline. A made two thirds of the rise is arithmetic; X caused A’s growth needs its own evidence.
    2. 
          
  2. Every claim carries its level. Claims the source cannot settle go to the claims ledger as data requests.
    3. 
          
  3. Learning before intervention. A costly or irreversible action with evidence missing becomes an investigation.
    4. 
          
  4. Trust is visible. Mode, source, generated, period, cutoff, checks, definitions, access and caveats, on the page.
    5.
